# 课程包格式（第一版）

> 对应设计书 §4.1 / §5.3 / §6.2；验收脚本：`npm run validate:course -- courses/demo`。
> 剧本语法保持 WebGAL 兼容子集，破坏性变更需先更新设计书（AGENTS.md #2）。
>
> **当前版本状态（2026-11-27）**：学习端课程接口已抽象为通用 `CourseProvider`，默认实现固定无课；本格式、校验器与存储代码保留给后续课程实现，学习端与管理端 UI 暂不开放课程入口。

## 目录结构

```
course/
├── course.json        # 元数据
├── start.txt          # 剧本入口（WebGAL 惯例）
├── scenes/*.txt       # 可选：分场景剧本
├── challenges/*.json  # 挑战定义
├── judges/*.json      # 判题配置
└── assets/            # SVG 立绘/背景等文本资源
```

创作目录先用 `node scripts/pack-course.mjs courses/xxx xxx.pack.json` 打成
`Record<相对路径, 文件文本>` 的 JSON，再由管理员通过
`POST /api/v1/admin/courses` 上传；学员端只能凭登录会话经 `GET /api/v1/courses/:id/pack` 拉取。

## course.json

```json
{
  "id": "codequest-demo", "slug": "demo", "title": "演示课程",
  "summary": "简介", "langs": ["javascript", "python", "cpp", "shell"],
  "difficulty": "beginner", "entry": "start.txt"
}
```

## 剧本语法

以 `;` 结束语句，支持 `//` 注释；`命令:内容 -参数=值;`。

| 语句 | 说明 |
|---|---|
| `标题` | `title:第一章;` |
| 演出 | `changeBg:main;`、`changeFigure:mentor;`、`bgm:theme;` |
| 对话 | `导师:台词;`（说话人糖衣）或 `say:导师:台词;` |
| 门控 | 任意语句带 `-when=pass_js==true` 才执行；支持 `==` / `!=` / 裸变量名 |
| 变量 | `setVar:name=value;`（true/false/数字自动转型） |
| 选项 | `choose:提示 -options=代码=codePath|终端=termPath;`，配合 `label:name;` 与 `jump:name;` |
| 代码挑战 | `code:ch01_js_hello -lang=javascript -onPass=pass_js;` |
| 终端挑战 | `term:sh01 -preset=bandit-l1 -mode=script|explore -unlock=pass_sh;` |
| 令牌门 | `token:CQ{...} -onPass=pass_token;`（Bandit 式解锁） |
| 提示 | `hint:hints/hint1.txt;` |
| 结束 | `end;` |

## challenge JSON

```json
{
  "id": "ch01_js_hello", "title": "让屏幕说 hello", "description": "**目标**：输出 hello",
  "lang": "javascript", "mode": "code", "template": "// TODO\n",
  "judge": "j_js_hello", "requireAllGoals": false,
  "goals": [
    { "id": "g-log", "text": "使用 console.log", "check": { "kind": "source-regex", "pattern": "console\\.log" } },
    { "id": "g-judge", "text": "通过全部测试点", "check": { "kind": "testcase", "all": true } }
  ]
}
```

- 剧本中的 `code:` 打开代码工作台，`term:` 打开终端工作台；挑战 JSON 的 `mode` 字段声明对应类别。
- `termMode: "explore"` 是 Bandit 式探索关：xterm 直接连接 container2wasm 常驻真实容器，命令在容器文件系统中执行；找到令牌并关闭终端后，在剧情里用 `token:` 提交。
- `termMode: "script"` 使用 Monaco 编辑 shell 脚本，并在同一常驻容器中串行运行与判题。
- Shell 题目的 `presetFiles` 键必须是容器内绝对路径，启动时通过 busybox 真实写入文件。C/C++ 模板题在 `presetFiles` 中用特殊键 `__template_wasm_base64` 携带预编译 wasm；JS/Python 运行时当前不消费 `files`。
- Shell 初始文件与 stdin 合计上限 512 KiB，脚本与 stdin 合计上限 512 KiB；每次运行 stdout/stderr 各限制 1 MiB。
- `goals.check.kind`：`source-regex` / `source-not-regex` / `output-contains` / `output-regex` /
  `exit-code` / `file-exists` / `command-stdout` / `testcase`。`file-exists` / `command-stdout` 在同一 Shell 容器会话中真实探测。
- goals 是过程引导；`requireAllGoals: false` 时不阻断提交，为 `true` 时必须全部完成后才允许提交，最终分数仍由 judge 产生。

## judge JSON

```json
{
  "id": "j_js_hello",
  "cases": [
    { "id": "t1", "name": "样例", "stdin": "", "expected": "hello\n", "mode": "eol" }
  ]
}
```

比对模式：`exact`（逐字节）/ `eol`（忽略行尾空白与末尾换行，默认）/ `ws`（忽略全部空白差异）/
`regex-line`（expected 每行是正则）/ `numeric-tol`（数值相对容差）。
判题按顺序跑完所有测试点，给出加权分数与首个失败点的行级 diff。

## 验收清单

1. `npm run validate:course -- <目录>` 通过；
2. 管理员上传后学员登录可拉取并走完剧情；
3. 每个挑战的代码模板、`TODO` 锚点、judge 预期输出与实际运行结果一致（先在浏览器跑一次「提交判定」）。
