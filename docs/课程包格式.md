> 对应设计书 §4.1 / §5.3 / §6.2 与 [RPGJS + Cloudflare 单边界架构设计](RPGJS-Cloudflare架构设计.md)。
> **当前代码仍保留历史 WebGAL 文本包用于迁移；`start.txt`、`say/choose/changeBg/-when` 不属于 v0.9 目标格式，后续必须删除。**

## 目录结构

```
course-rpgjs/
├── project.json              # 创作期元数据
├── maps/*.tmx                # Tiled 地图
├── tilesets/*.tsx            # Tiled 瓦片集
├── media/*                   # PNG/WebP/SVG 等图片
├── sounds/*                  # OGG/MP3/WAV
├── events/*.json             # 教师事件块
├── database/*.json           # 物品、技能、职业、状态等
├── challenges/*.json         # 代码、终端、场景脚本挑战
├── judges/*.json             # 公开判题配置
├── licenses/*                # 素材许可与来源登记
└── sealed/judges/*.json      # 隐藏判题数据，只进 sealed
```

发布产物为 `artifact.json` + `content/` 文件树。`artifact.json` 记录：

- 课程 id、slug、标题、语言、难度、版本；
- `engine: "rpgjs"` 与 `shellVersion`；
- 起始地图、出生点和初始事件；
- 每个文件的路径、SHA-256、大小、MIME、layer；
- 素材许可与 sealed 哈希/数量。

学员端通过 Cloudflare Worker 鉴权 API 获取 manifest 和按需下载内容；不提供整包侧载。编辑器输出优先使用 TMX/TSX；若继续输出 Tiled JSON，必须实现 `provideLoadMap()` 适配层。

## challenge JSON

```json
{
  "id": "ch01_js_hello", "title": "让屏幕说 hello", "description": "**目标**：输出 hello",
  "lang": "javascript", "mode": "code", "template": "// TODO\n",
  "judge": "j_js_hello", "requireAllGoals": false,
  "goals": [
    { "id": "g-log", "text": "使用 console.log", "check": { "kind": "source-regex", "pattern": "console\\.log" } },
    { "id": "g-judge", "text": "通过全部测试点", "check": { "kind": "testcase", "all": true } }
  ]
}
```

- 教师事件块通过 challenge-id 打开代码/终端工作台；挑战 JSON 的 `mode` 字段声明对应类别。
- `termMode: "explore"` 是 Bandit 式探索关：xterm 连接 container2wasm 常驻真实容器；找到令牌后通过 RPGJS GUI 的 `showInput` 提交。
- `termMode: "script"` 使用 Monaco 编辑 shell 脚本，并在同一常驻容器中串行运行与判题。
- Shell 题目的 `presetFiles` 键必须是容器内绝对路径，启动时通过 busybox 真实写入文件。C/C++ 模板题在 `presetFiles` 中用特殊键 `__template_wasm_base64` 携带预编译 wasm；JS/Python 运行时当前不消费 `files`。
- Shell 初始文件与 stdin 合计上限 512 KiB，脚本与 stdin 合计上限 512 KiB；每次运行 stdout/stderr 各限制 1 MiB。
- `goals.check.kind`：`source-regex` / `source-not-regex` / `output-contains` / `output-regex` /
  `exit-code` / `file-exists` / `command-stdout` / `testcase`。c2w 只有 Shell/终端接口，因此 `file-exists` / `command-stdout` 必须实现为容器内 shell 探针，并判定其 stdio/退出码；它们不是独立的世界状态 API。
- goals 是过程引导；`requireAllGoals: false` 时不阻断提交，为 `true` 时必须全部完成后才允许提交，最终分数仍由 judge 产生。

## judge JSON

判题分为两条并行轨道：

- **stdio 轨**：五门语言统一产生 `stdout/stderr/exitCode`，使用下面的 OI judge；Shell/c2w 也走此轨。
- **世界状态轨**：RPGJS 学生脚本使用 `kind: "script"`，断言 `SimWorld` 的 state/effects/listeners/texts。

两条轨共享 goals、成绩和进度；同一挑战默认选择一个 `judge`，不把世界状态结果伪装成 stdio。

### stdio 轨（OI）

```json
{
  "id": "j_js_hello",
  "cases": [
    { "id": "t1", "name": "样例", "stdin": "", "expected": "hello\n", "mode": "eol" }
  ]
}
```

比对模式：`exact`（逐字节）/ `eol`（忽略行尾空白与末尾换行，默认）/ `ws`（忽略全部空白差异）/
`regex-line`（expected 每行是正则）/ `numeric-tol`（数值相对容差）。
判题按顺序跑完所有测试点，给出加权分数与首个失败点的行级 diff。

### RPGJS 场景脚本 judge

脚本题仍使用 `lang: "javascript"` 与 `mode: "code"`，但 judge 文件用 `kind: "script"` 选择世界状态轨；省略 `kind` 时默认 `oi`（stdio 轨）。两条轨并行存在，互不替代。

```json
{
  "id": "j_rpg_move",
  "kind": "script",
  "init": { "seed": 7, "player": { "gold": 10 } },
  "cases": [
    {
      "id": "move4",
      "name": "向上移动四步",
      "call": { "fn": "move" },
      "expect": {
        "effect:player.moveRoutes:args.0.0.up": 4,
        "player.gold": 10
      }
    }
  ]
}
```

- `init` 是每次 attempt 的不可变初始世界；`cases` 至少一项，每个 case 必须且只能指定 `call`、`fire`、`emit` 之一。
- `expect` 支持部分状态路径（如 `player.gold`、`events.guard.x`、`vars.x`）、`{ min, max }` 范围、`returns`、`error`、`effectsInclude`/`effectsExclude`、`texts`/`notifications`，以及 `effect:<name>:<path>` 效果参数断言。
- `game.player.move(way, times)` 是课程门面 API；移动在 `SimWorld` 中记录 `player.moveRoutes` 效果，不直接更新坐标，必须断言效果参数。
- 每个 case/提交新建 `SimWorld`。失败 attempt 的 state/effects 直接丢弃，下一次从同一 `init` 重放；通过后才允许提交剧情副作用。
- `catalog`、`requiredExports`、`limits` 可选；学生脚本只经 Worker 内的 `@rpgjs/script` 解释器执行，不在主线程或后端执行。
- 当前文本课程包没有 sealed 分流，脚本 judge 只用于公开样例；隐藏用例进入 `cq-sealed` 的链路完成前不得随包下发。

## 验收清单

1. `npm run validate:course -- <目录>` 通过；script judge 的正反例均被校验；
2. 管理员上传后学员登录可拉取并走完剧情；
3. 每个挑战的代码模板、`TODO` 锚点、judge 预期输出与实际运行结果一致（先在浏览器跑一次「提交判定」）。
4. script judge 的失败 attempt 不泄漏 state/effects，下一 attempt 从同一 `init` 重放；通过 attempt 才触发一次提交。
