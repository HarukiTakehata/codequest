# 能力矩阵：各运行时的文件系统与网络支持（2026-11-24 核查）

> 配套设计书 v0.3 §5.2。范围：`packages/runtime-*` 五个运行时 + 容器会话；「教学影响」列给出出题约束。
> 原则性结论先行：**跨会话持久化不依赖任何运行时内建能力，统一由宿主层（SPA + IndexedDB）承担**；**网络默认全禁，需要联网的教学任务显式声明并受浏览器 CORS 约束**。

## 1. 总矩阵

| 运行时 | 文件系统（初始注入） | 运行中读写 | 跨会话持久 | 出站 HTTP | 原始 socket / 监听 | 教学影响 |
|---|---|---|---|---|---|---|
| **Pyodide**（Python） | `pyodide.FS.writeFile` 注入；默认 MEMFS | ✅ 完整 `pathlib`/`os`/`open` | ✅ **原生支持**：挂载 `FS.filesystems.IDBFS` + `FS.syncfs(0/1)`（官方文档明示，注意 syncfs 异步语义）；Chromium 还可 `mountNativeFS` | ⚠️ 仅 `pyodide.http.pyfetch`（fetch 管道）；`urllib/requests` 需 `pyodide-http` 补丁 | ❌ 无 socket 模块 | 文件 IO 章节可用；「数据持久化」课可作为 IDBFS 现成案例；网络章节只能教 fetch 系 |
| **JS Worker** | 宿主 `postMessage` 注入 files map | ✅ 运行时内纯内存对象/自实现 FS | ⚠️ 无内建：需宿主桥接 IndexedDB | ✅ `fetch`/`WebSocket` 全量（受 CORS） | ❌（浏览器限制） | **唯一可教真实网络编程**的语言层（HTTP/WS 客户端）；文件系统要自造或教 OPFS |
| **wasm-clang**（C/C++） | 内存 FS，项目目录可从挂载点读 | ✅ stdio/fopen（限内存 FS） | ❌ 内存 FS，宿主注入+运行后收集 | ❌ 未见 socket 实现（WASI 式能力层） | ❌ | 文件 IO 教学限定「注入→读写→输出」闭环；网络章节不可行（socket 不可用） |
| **teavm-javac**（Java） | 内存 FS（宿主注入） | ✅ `java.io`（classlib 子集）；`java.nio.file` 为 stub（编译可过、运行抛 UnsupportedOperation） | ❌ 内存 FS | ⚠️ classlib 提供 `THttpURLConnection`（XHR 实现，出站 HTTP 可用）；受 CORS | ❌ `java.net` Socket 官方文档明示不支持（stub 会抛异常） | 文件章节避开 `java.nio.file`，用 `java.io.*`；网络章节只能教 HttpURLConnection 层 |
| **wasi-sh**（Shell 脚本判题） | `run({files})` 注入内存 FS | ✅ busybox applets 全套文件操作 | ❌ 单次运行即弃 | ❌（wget 需外部提供 socket） | ❌ | 文本/文件处理判题首选；无网络无持久，天然干净 |
| **container2wasm 会话**（Shell 交互/进阶） | 9p 挂载初始文件系统 + rootfs 预置 | ✅ 真 Linux 全量（含权限、软链） | ⚠️ 会话内持久、刷新丢失；WASI 路径支持 `--mapdir` 映射宿主目录，浏览器端需宿主层把 IndexedDB 背板的目录映射进去（增强项，未内建） | ⚠️ fetch 代理出站 HTTP/HTTPS（**CORS 受限，apt-get 不可用**）；或 WebSocket 委托宿主机 `c2w-net` | ⚠️ 容器内 loopback 监听可行（推断，M4 spike 核实）；对外端口无 | 探索式 shell 学习的主场；「持久化工作目录」是增强项；网络教学限定出站 HTTP 与容器内 loopback |
| （备选）v86 + Alpine | ext2 磁盘 + OPFS/IndexedDB 背板（terminal-web-vm 实证） | ✅ 全量 | ✅ 磁盘快照存 IndexedDB | WISP v1 WebSocket 出站 | 同 container2wasm | 仅当 container2wasm 性能不达标时启用 |

## 2. 统一约定（宿主层职责）

1. **注入**：所有运行时的初始文件集统一走 `RunRequest.files`（§5.1）；容器会话例外——用 9p 挂载课程快照目录。
2. **持久化**：统一规则「课程快照进、运行产出收集出」。需要跨会话保留的产物（如学生在容器里写的脚本），由宿主层在关键节点抓 diff 存 IndexedDB（含后端同步，R8），**不在运行时内做持久化**——避免五套运行时各自维护持久化语义。Pyodide 的 IDBFS 仅在「教学目标就是浏览器持久化」时使用并显式声明。
3. **网络策略**：默认禁网（上述矩阵表明五个运行时里四个天然禁网）。JS 与 Python 的 fetch 类任务是唯一「教网络」的路径，运行前显示 CORS 风险说明；container2wasm 会话的 fetch 代理默认开启但课程可关；任何层级不向学员暴露原始 socket。
4. **判题影响**：文件状态检查（goals `file-exists`）只在 container2wasm 会话可做运行时真实检查；其余运行时的文件类 goals 用「收集运行后 FS diff」在宿主层判定（实现于 `packages/runtime-*` 各自的 collect 接口）。

## 3. 出题速查（哪种章节放哪层）

| 章节类型 | 可行层 | 备注 |
|---|---|---|
| 纯算法 + stdin/stdout | 全部五层 | 无差别 |
| 文件读写/文本处理 | Pyodide / wasm-clang / Java(java.io) / wasi-sh / 容器 | Java 避开 nio.file |
| 脚本 + 真实文件系统操作（ls/grep/权限） | container2wasm 会话（或 v86） | §5.5.1 状态判题 |
| HTTP/WS 客户端编程 | JS Worker（全量）/ Python（pyfetch）/ Java（THttpURLConnection） | 受 CORS，教「浏览器网络模型」本身就是知识点 |
| TCP/socket 原语 | ❌ 无层可行（除容器内 loopback 实验） | 不排期 |
| 长生命周期工程环境（Gradle/Spring 进阶） | container2wasm JDK 镜像（补充选型 §7 C 层） | MJ 系列立项时细化 |
